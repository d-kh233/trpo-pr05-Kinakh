# trpo-pr05-Kinakh
# Практическая работа №5. PHP ООП. Классы, конструкторы и модели предметной области

## Краткое описание результата
Веб-приложение каталога товаров на PHP 8+ с переходом от процедурного подхода и сырых массивов к объектной модели предметной области (`Category`, `Product`) и сервисному слою (`CatalogService`). Данные загружаются из JSON-файлов каталога `dataset/`, фильтруются по выбранной категории через GET-запрос и выводятся в семантическом HTML-интерфейсе с экранированием и агрегированной статистикой.

## Используемые технологии
- PHP 8.1+ (строгая типизация `declare(strict_types=1);`, Constructor Property Promotion, исключения `InvalidArgumentException`)
- HTML5 (семантическая разметка: `<header>`, `<main>`, `<section>`, `<article>`)
- CSS3 (адаптивная сетка карточек на CSS Grid)
- JSON / CSV (`dataset/`)

## Требования к окружению и инструкция чистого запуска
1. Убедитесь, что установлен PHP версии 8.1 или выше:
   ```bash
   php -v
   ```
2. Клонируйте репозиторий и перейдите в корень проекта:
   ```bash
   git clone <URL_репозитория>
   cd trpo-pr05-Kinakh-1
   ```
3. Запустите встроенный веб-сервер PHP из корня проекта, указав `public` корневой директорией:
   ```bash
   php -S localhost:8000 -t public
   ```
4. Откройте в браузере адрес:
   ```text
   http://localhost:8000
   ```

## Схема потока данных и ответственность элементов

```text
dataset/*.json → Category / Product → CatalogService → public/index.php
```

1. **Модели (`Category`, `Product`)** — описывают сущности предметной области и их поведение:
   - принимают обязательные параметры через `__construct(...)`;
   - гарантируют валидное состояние объекта (выбрасывают `InvalidArgumentException` при пустом названии, некорректном `id` или неположительной цене);
   - содержат предметные методы (`formattedPrice()`, `discountedPrice()`, `formattedDiscountedPrice()`, `belongsToCategory()`, `active()`);
   - не содержат HTML-разметки и логики чтения файлов.
2. **Сервис (`CatalogService`)** — связующий слой между данными и интерфейсом:
   - проверяет наличие файлов `products.json` и `categories.json`, читает и декодирует JSON;
   - выполняет гидратацию (преобразует ассоциативные массивы в массивы объектов `Category` и `Product`);
   - фильтрует товары по категории (`filterByCategory()`), вычисляет агрегированные значения (`getAveragePrice()`) и сопоставляет `categoryId` с названием категории (`categoryNameById()`).
3. **Представление (`public/index.php`)** — точка входа и слой вывода:
   - подключает модели и сервис через `require_once`;
   - читает параметр фильтра из `$_GET['category']`;
   - получает от сервиса готовые объекты, экранирует все выводимые значения через `htmlspecialchars` и формирует HTML-страницу;
   - демонстрирует обработку ошибочного сценария создания объектов через `try ... catch (InvalidArgumentException)`.

## Что изменилось после Шага 4 (добавление предметных методов)
После добавления предметных методов (`formattedPrice()`, `discountedPrice()`, `formattedDiscountedPrice()`, `belongsToCategory()`, `active()`) класс `Product` перестал быть простым хранилищем данных с геттерами («анемичной моделью»). Расчёт скидки, форматирование цены и проверка принадлежности к категории выполняются внутри самой модели, а `index.php` и `CatalogService` работают с готовым контрактом методов и не дублируют вычисления в HTML-шаблоне.

## Краткий сценарий проверки
1. Открыть `http://localhost:8000` — на странице отображаются все товары из `dataset/products.json`, их категории, цены (включая дробные), цены со скидкой, статус активности, общее количество и средняя цена.
2. Выбрать категорию в выпадающем списке и нажать «Показать» — список карточек, счётчик и средняя цена пересчитываются, выбранная категория сохраняется в `<select>`.
3. Перейти по адресу `http://localhost:8000/?category=999` — отображается сообщение о пустом результате без PHP warnings/notices.
4. Проверить нижний блок «Проверка валидации конструкторов» — отображаются перехваченные сообщения `InvalidArgumentException` при попытке создать некорректные `Category` и `Product`.
